# The Daily Ten Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A two-player daily trivia website played on one shared screen, with ten questions a day, hints, hidden lock-in, a per-day score and an all-time scoreboard, shipping with Day 1 (Rembrandt and Van Gogh).

**Architecture:** A static site with no build step. Pure logic (scoring, day session, score store) lives in small ES modules tested with `node --test`; one UI module renders into `#app`. Days are JSON files fetched at run time. Two thin shells load the same files: `index.html` (full document, for GitHub Pages) and `artifact.html` (fragment, for the Artifact publish, which adds its own document skeleton).

**Tech Stack:** HTML, CSS, vanilla JavaScript (ES modules), JSON data, Node 26 built-in test runner. Google Fonts is the only external resource.

**Spec:** `docs/design-draft.md`

## Global Constraints

- All paths below are relative to the repository root.
- No frameworks, no bundler, no npm dependencies. `package.json` holds only `"type": "module"` and a `test` script (`node --test tests/`).
- Ten questions per day, four options each, one hint each.
- Default scoring from the spec: 3 correct without hint, 2 correct with hint, 0 wrong. The rule is one function written by the user (Task 2); nothing else may hard-code 3, 2 or 30.
- Days are numbered, not calendar-bound. A replay never changes the score.
- Every colour is a CSS token defined on bare `:root`, redefined for dark under `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) }` and `:root[data-theme="dark"]`. `body` sets an explicit background.
- Side gutter `max(16px, env(safe-area-inset-left|right, 0px))`; works at 400 px wide with no horizontal scroll.
- No `alert()`, `confirm()`, `prompt()`, `window.print()`. Confirmations are built into the page.
- Every `localStorage` call is wrapped in try/catch; the game must play without storage.
- Images are local copies (about 1,280 px wide), public domain only, with neutral file names (`p01.jpg`) and alt text that does not name the painting. The credit appears only after the reveal.
- All user-entered text (player names) is inserted with `textContent`, never `innerHTML`.
- Commit and push happen only in Task 8, after the user's go-ahead.

## Review Focus

1. **Every available day has been played** (true the evening after Day 1): Home says so plainly and offers a practice replay; it never shows a broken "Play" button. Test in Task 4 (`nextUnplayedDay` returns `null`) and browser check in Task 7.
2. **The page is reloaded in the middle of a day:** the day resumes at the same question with the same scores. Test in Task 4 (`inProgress` round-trips through save and load).
3. **Storage is blocked or throws** (private window, artifact preview): the game plays normally and Home shows "Scores are not being saved on this device". Test in Task 4 with a throwing storage stub.
4. **A wrong or damaged backup is pasted:** a clear message, and the existing score is untouched. Test in Task 4.
5. **Keys pressed at the wrong time** (typing player names, after the reveal, a third lock-in): no pick is registered. Test in Task 3 (`keyToPick`, `lockIn` after reveal).

### Task 3: Day session logic

**Files:**
- Create: `js/game.js`, `tests/game.test.js`

**Interfaces:**
- Consumes: a day object (Task 1) and a `pointsFor` function (Task 2), passed in as an argument so tests use a stub.
- Produces:
  - `createSession(day, pointsFor)` → `Session = { dayId, index, phase: "answering"|"revealed"|"finished", picks: { a: number|null, b: number|null }, hintOpen: boolean, hintUsed: { a: boolean, b: boolean }, results: Result[] }`
  - `Result = { questionId, picks: {a,b}, correct: {a,b}, hintUsed: {a,b}, points: {a,b} }`
  - `lockIn(session, player, optionIndex)`, `unlock(session, player)`, `openHint(session)`, `reveal(session)`, `next(session)` — each returns a new session and returns the same session unchanged when the move is not allowed.
  - `bothLocked(session)` → boolean; `totals(session)` → `{ a, b }`; `maxPoints(day, pointsFor)` → number (10 × `pointsFor({correct:true, hintUsed:false})`).
  - `keyToPick(key)` → `{ player: "a"|"b", option: 0..3 } | null` with `1 2 3 4` → player a, `7 8 9 0` → player b.

Rules the tests pin:
- A player's `hintUsed` is the value of `hintOpen` at the moment of their latest lock-in. Locking before the hint, then unlocking and re-locking after it, counts as hint used.
- `reveal` is allowed only when both are locked; it appends a `Result` and sets phase `revealed`. `lockIn`, `unlock` and `openHint` do nothing after the reveal.
- `next` after the tenth reveal sets phase `finished`; otherwise it advances `index` and clears `picks`, `hintOpen`, `hintUsed`.
- Sessions are plain JSON (they are saved to storage in Task 4).

- [ ] **Step 1:** Write `tests/game.test.js` covering each rule above, plus: `lockIn` with an option outside 0–3 or an unknown player is ignored; `keyToPick("5")` and `keyToPick("a")` return `null`; a full ten-question run with a stub rule (5 / 1 / 0) gives the expected `totals` and `maxPoints` of 50.
- [ ] **Step 2:** Run it; expect failure (module missing).
- [ ] **Step 3:** Implement `js/game.js`.
- [ ] **Step 4:** Run `node --test tests/game.test.js`. Expected: PASS.

### Task 4: Score store, summary and backup

**Files:**
- Create: `js/store.js`, `tests/store.test.js`

**Interfaces:**
- Produces:
  - `STORAGE_KEY = "daily-ten:v1"`
  - `emptyState()` → `{ version: 1, names: { a: "", b: "" }, history: [], inProgress: null }`
  - `loadState(storage)` → `{ state, persistent: boolean }` (never throws; `persistent` is false when storage is missing or throws; unreadable saved data yields `emptyState()`)
  - `saveState(storage, state)` → boolean (false when the write failed)
  - `recordDay(state, day, session, playedOn, maxPoints)` → new state with a `HistoryEntry = { dayId, number, theme, title, playedOn: "YYYY-MM-DD", maxPoints, totals: {a,b}, results: Result[] }` appended and `inProgress` cleared. If `dayId` is already in the history the state is returned without a new entry (practice replay).
  - `nextUnplayedDay(state, dayList)` → the lowest-numbered index entry not in the history, or `null`.
  - `summary(state)` → `{ daysPlayed, points: {a,b}, dayWins: { a, b, ties }, byTheme: { [theme]: { a: { correct, total }, b: { correct, total } } } }`
  - `exportBackup(state)` → JSON string; `importBackup(text)` → state, or throws `Error` whose `message` is fit to show the user ("This is not a Daily Ten backup." / "This backup is damaged and cannot be read.").

- [ ] **Step 1:** Write `tests/store.test.js`: round trip through a fake storage object, including `inProgress` (Review Focus 2); a storage whose `getItem` and `setItem` throw gives `persistent: false` and `saveState` false (Review Focus 3); garbage in storage gives `emptyState()`; `recordDay` twice with the same day adds one entry; `nextUnplayedDay` returns `null` when all are played (Review Focus 1); `summary` over three synthetic days gives the right points, wins, a tie and per-theme counts; `importBackup` rejects `"hello"`, `"{}"`, a wrong `version` and a history entry without `totals`, and accepts `exportBackup` output unchanged (Review Focus 4).
- [ ] **Step 2:** Run it; expect failure.
- [ ] **Step 3:** Implement `js/store.js`.
- [ ] **Step 4:** Run `node --test tests/`. Expected: all PASS except `scoring.test.js` until Task 2 Step 3.

### Task 5: Page shells and styles

**Files:**
- Create: `index.html`, `artifact.html`, `css/app.css`

**Interfaces:**
- Produces: both shells contain `<div id="app"></div>`, load `css/app.css`, the Google Fonts stylesheet, and `<script type="module" src="js/main.js">`. `artifact.html` has no doctype, `html`, `head` or `body` tags; it starts with `<title>The Daily Ten</title>` and `<meta name="claude:viewport-fit-sides" content="cover">`. `index.html` is a full document with charset and viewport meta and the same title.

After the reveal the label gains the real caption (artist, title, year, museum), as on a museum placard. Two player colours that are not green or red; green and red are reserved for right and wrong. Tokens for colour and type go at the top of `css/app.css`, with a one-line comment stating the layout concept.

### Task 6: UI

**Files:**
- Create: `js/ui.js`, `js/main.js`
- Create: `.claude/launch.json` in the parent folder (static server for the preview: `python3 -m http.server 4173 --directory daily-trivia`)

**Interfaces:**
- Consumes: everything produced by Tasks 1–4.
- Produces: `main.js` fetches `days/index.json`, calls `loadState(localStorage)` and starts the UI. Views: `setup` (two names, first run only), `home`, `question`, `finished`, `backup`.

Behaviour the spec leaves to this task:
- Home: next day card with "Play Day N", or "Continue Day N, question k of 10" when `inProgress` is set, or the all-played message with "Practise Day N again". Scoreboard (points, day wins, ties, accuracy by theme) and the history table below. With no days played, the scoreboard shows a designed empty state.
- Question: image (click or Enter to enlarge), question, four options as a read-only list labelled A–D, a pad of A–D buttons per player, a "Change" button for a locked player, one "Hint" button, and a "Reveal" button enabled when both are locked. Number keys via `keyToPick`, ignored while focus is in a text field and outside the answering phase.
- Reveal: correct option marked, each player's pick and points shown, explanation, image credit, sources as links, "Next question" / "See the result".
- If an image fails to load, the question switches to the text-only layout.
- The session is saved to `inProgress` after every lock, hint, reveal and next. Practice replays are never saved.
- Backup: "Copy backup" (clipboard, with select-the-text fallback), a text box to paste a backup into with "Restore", a file input to restore from a file, "Download backup file" shown only when the page is not inside a frame, and "Reset all scores" with an in-page second confirmation.
- When `persistent` is false, Home shows "Scores are not being saved on this device".
